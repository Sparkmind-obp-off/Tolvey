# TOLVEY — Operator Playbook

## Daily operating loop

1. Capture demand.
2. Classify demand.
3. Identify repeated problems.
4. Score opportunity.
5. Select one product hypothesis.
6. Define the smallest useful offer.
7. Build/package it.
8. QA.
9. Publish canonical product record.
10. Distribute to selected channels.
11. Monitor transactions.
12. Deliver.
13. Capture feedback.
14. Update product evidence.
15. Decide: improve, expand, pause, or archive.

## Operator rule

Never build a large system to avoid doing the first manual transaction.

Manual first -> repeatable process -> automation.

## Product launch checklist

- buyer identified
- problem documented
- offer defined
- price defined
- product assets complete
- delivery tested
- checkout tested
- refund/support path defined
- analytics tagged
- channel copy prepared
- publication verified

## Commerce checklist

- product ID/SKU
- price
- payment path
- fulfillment path
- order capture
- customer support
- channel attribution
- reconciliation

## Weekly review

Ask: What demand appeared? What actually sold? Which channel produced qualified traffic? Which product was used? What caused refunds or confusion? What should be removed? What should be improved? What should be automated?

## Anti-patterns

- building before demand;
- launching ten products at once;
- treating followers as revenue;
- assuming marketplace presence equals distribution;
- copying channel-specific data manually without a canonical record;
- adding integrations before volume justifies them;
- turning TOLVEY into a multi-vendor marketplace prematurely.
